# Security Policy

## Supported Versions

AspNetCore.Ignite versions track the Apache Ignite version they target (e.g. `2.19.0` targets Apache Ignite `2.19.0`,
and is built on Apache Ignite `2.18.0` until `2.19.0` is released). Only the latest release receives security fixes.
This applies to all artifacts produced by this repository:

| Artifact                                                       | Supported     |
|----------------------------------------------------------------|---------------|
| `AspNetCore.Ignite` NuGet package (nuget.org, GitHub Packages) | 2.19.x        |
| `aspnetcore.ignite-server` Docker image (GHCR)                 | 2.19.x        |
| Older versions                                                 | Not supported |

If you find a security issue in an older version, please first check whether it still reproduces on the latest
version. If you can't upgrade, let us know why so we can better understand your situation.

## Reporting a Vulnerability

**Please do not report security vulnerabilities through public GitHub issues, discussions or pull requests.**

Report them privately through
[GitHub Security Advisories](https://github.com/dradoaica/AspNetCore.Ignite/security/advisories/new)
("Report a vulnerability" under the repository's **Security** tab).

Please include as much of the following as you can:

- Affected artifact (NuGet package, server, Docker image) and version
- Configuration involved (e.g. `appsettings.json` values, Spring XML config, persistence/SSL/authentication settings,
  Kubernetes discovery)
- Step-by-step instructions to reproduce the issue
- Proof-of-concept or exploit code, if available
- Impact of the issue and how an attacker might exploit it

You should receive an acknowledgement within a few days. We will keep you informed of the progress toward a fix and
may ask for additional information. Please give us a reasonable amount of time to release a fix before any public
disclosure.

## Scope

In scope:

- Code in this repository: the `AspNetCore.Ignite` library, the `AspNetCore.IgniteServer` host, the `Dockerfile`, the
  bundled Spring XML configuration files and the GitHub Actions workflows.

Out of scope — please report these upstream instead:

- Vulnerabilities in Apache Ignite itself (Java core, .NET bindings, thin client) → the
  [Apache Software Foundation security team](https://www.apache.org/security/).
- Vulnerabilities in third-party dependencies (Serilog, Polly, Jetty, Jackson, etc.) → the respective project. We do
  want to hear about vulnerable dependency versions shipped by this project, so we can upgrade them.
- The Helm chart → [dradoaica/helm-charts](https://github.com/dradoaica/helm-charts).

## Securing Your Deployment

The defaults in this repository are meant for **local development only**. Before running AspNetCore.IgniteServer in
any shared or production environment:

- **Replace the bundled certificates.** The key stores and certificates in `src/AspNetCore.IgniteServer/config`
  (`server.jks`, `trust.jks`, `thin-client-cert.pfx`, password `123456`) are public sample files generated by
  `scripts/ssl/ssl.ps1`; they are only part of Debug builds, never of Release builds or the Docker image. Generate
  your own and never commit private keys.
- **Secure the cluster ports.** Ignite 2 does not authenticate nodes: anyone reaching the discovery (47500) and
  communication (47100) ports can join the cluster. Enable `USE_SSL` (nodes need a certificate the trust store trusts)
  and/or restrict these ports, e.g., with a Kubernetes NetworkPolicy (see the README). Keep `PEER_ASSEMBLY_LOADING`
  off unless every node is trusted: it lets nodes run code on each other.
- **Keep REST off** (`REST_ENABLED=false`, the default) unless needed: it is served over plain HTTP.
- **Set all passwords.** `appsettings.json` ships with empty `IGNITE_USER_PASSWORD` and `SSL_*_PASSWORD` settings (the
  default `ignite` user then keeps its well-known password `ignite`). Set them via environment variables or Kubernetes
  secrets.
- **Keep authentication enabled and enable SSL** (`ENABLE_AUTHENTICATION` is on by default; `USE_SSL` and
  `USE_CLIENT_SSL` are off by default).
- **Restrict network exposure.** The image exposes Ignite discovery/communication ports (`47500`, `47100`), the thin
  client port (`10800`) and the management port (`9464`, health checks and `/metrics`); with `REST_ENABLED`, also the
  REST/HTTP ports (`8080`, `11211`). Only publish what your clients need and keep cluster-internal ports on a private
  network.
- **Keep up to date** with the latest release of this project, which picks up Apache Ignite and .NET security fixes.
